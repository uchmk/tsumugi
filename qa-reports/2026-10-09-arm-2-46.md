## ARM64

Findings from this lane (none of the rows concerned was `[x]` from x64):

1. **2.52: SGR styles.** In pwsh with `ESC[4m` (single underline), `ESC[9m` (strike) and `ESC[8m` (hidden): the single underline and the strike are **not drawn**, the hidden text is **shown** anyway (`[hid]` is visible, `r260a.png`), while dashed `ESC[4:5m` is drawn dashed (`r252*.png`). After an extended underline style/colour, `SGR 0` does not clear it, so the next text keeps the underline. The window close/reopen part was not done.
2. **2.55: Shift+Enter.** The PTY log shows no CSI-u for Shift+Enter in a Windows local pane: `\e[13;28;13;1;16;1_` (win32-input-mode, shift flag) goes to ConPTY, which turns it into a plain `\r` for git bash and nvim (`<S-CR>` is never seen); PSReadLine binds Shift+Enter to AddLine so it adds a line instead of running. Nothing to compare in the row's expectation (`CSI 13;2u`) was ever sent by tsumugi on Windows.
3. **2.54: `:checkhealth`.** nvim 0.12.5 `:checkhealth` prints `Terminal: unknown`, `$TERM: unknown`. nvim 0.12 reads the name from environment variables (`TERM_PROGRAM`, etc.), not from XTVERSION (`vim/health/health.lua` `detect_terminal()`), and tsumugi sets neither on this lane.
4. **2.48: `wezterm imgcat` panics.** The PTY log of that pane shows tsumugi answering `CSI >q` (XTVERSION), `CSI c` (DA1) and `CSI 18t` (`\e[8;28;76t`) but **no reply to `CSI 16 t`** (cell size in pixels), after which wezterm divides by zero (`wezterm\src\main.rs:383:10`). Any program that needs the cell size from `CSI 16 t` (wezterm imgcat, chafa in some modes) fails the same way.
5. **Focus out.** When the tsumugi window loses OS focus (Alt+Tab to another app), nvim in the pane is not sent `\e[O`; an app that wants to pause on focus loss never hears of it.
6. **2.58: Ctrl+C does not stop a running program in a pane.** Without and with a selection: pwsh `Start-Sleep 300` ran its full `took 5m0s`; `ping -n 100 127.0.0.1` ran all 100 packets (`took 1m40s`, 100 sent / 100 received); `Start-Sleep 25` interrupted by a raw `\x03` through `tsumugi send` ran the whole `took 25s`. The PTY log has `in key \e[67;46;3;1;8;1_ (Ctrl+c)` for each press, so the key reached the pane, but ConPTY never ended the child. At the idle prompt Ctrl+C does print `^C` (PSReadLine). A pane whose input stopped working (session 79: `ping`, then no echo for `send` and kit input although the prompt came back) is a possible second symptom; not reproduced on the other panes.
7. **Settings search.** The Settings search for "copy" finds nothing, so the "Copy a selection when the mouse lets go" row cannot be reached by search (reached by scrolling).

## Notes on how it was done

- `Send-Keys 'Ctrl+Shift+C'` (the kit's) gave no copy on this machine in two tries; the same chord with the modifiers held for 120 ms steps (keybd_event, Ctrl and Shift down, `C` down/up, then up) copied the selection at once. I treated that as a speed artefact of the injected input, not a bug (egui sees `Event::Copy` only when the modifier is already down).
- `tsumugi read` cannot see the alt screen (nvim); nvim autocmds wrote files instead.
- `make-testcheck -- --check` and `make-keycheck -- --check` print nothing and exit 0 when in sync (they print only when out of date).

### Proposals

- **Ctrl+C reaching ConPTY (finding 6): the most valuable one.** What: find why `CTRL_C_EVENT` is not generated on ARM64 (is `ENABLE_PROCESSED_INPUT` lost, or is the key-up never sent after the win32-input-mode key-down?). The PTY log only shows key-down records (`...;1;8;1_`); sending the matching key-up (`...;0;8;1_`) is the first thing to try. Size: small to find, small to fix. Why: a user cannot stop a running command.
- **Answer `CSI 16 t`** (`\e[6;<cell h>;<cell w>t`) next to the existing `CSI 18 t` reply. Why: wezterm imgcat, chafa and others divide by zero without it. Size: small.
- **Settings: a name for the terminal**: set `TERM_PROGRAM=tsumugi` and `TERM_PROGRAM_VERSION` in the pane's environment so that nvim `:checkhealth` and similar tools name it. Size: small.
- **A kit helper for held chords** (`Send-Keys -Hold` with 100 ms between steps) and for the mouse wheel / middle click / drag: I wrote them in scratch (`drag.ps1`, `mid.ps1`). Size: small; saves the next run a few turns.
- **Rows 2.46-2.49 need tools the machine lacks** (`img2sixel`, `chafa`, `kitten`, `imgcat`, a WSL distro). Either install them on the lanes, or move those rows to a person.
