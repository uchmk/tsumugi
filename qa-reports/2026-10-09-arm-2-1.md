## Bugs

**Bug 1 — a dragged divider is not saved on release** (rows 2.3, 2.15).
`crates/tsumugi/src/main.rs` ~:4190 clears `self.dragging` when `!held`
(`ui.input(|i| i.pointer.primary_down())`). On the frame the button goes up, `primary_down()` is already false, so
`dragging` is `None` before `tsumugi_layout::ui::dividers` returns `Moved::Released` at ~:4521. The `Released` arm
then has nothing to send (`self.dragging.take()` is `None`) and `client.set_layout` is never called, so the split goes
back to the old ratio. Not fixed here (this run only reports). `Halved` is unaffected: it sends at once.

## Kit notes

- `Invoke-Tsumugi ls --json` throws a `Timeout` int conversion error; `-Arguments @('ls','--json')` works.
- The kit has no mouse-drag function; drags were done with `mouse_event` and `SetCursorPos`.
- `Send-Keys` wants chord names (`Esc`), not `{ESC}`.
- `tsumugi read` straight after `send` can return stale text; waiting 4 s was needed.

### Proposals

- Add `Send-Drag` (down, moves, up) to `scripts/wintest-kit.ps1`.
- Fix Bug 1 in `main.rs`: do not clear `dragging` on the release frame (or keep the last `Dragging` layout until `Released` is handled).
- Make `Invoke-Tsumugi` accept positional arguments, or document `-Arguments`.
- Move 2.10 out of the unattended queue (needs a person with a real IME).
