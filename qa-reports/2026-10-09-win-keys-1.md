## Not ticked

- `Ctrl+=` (`font_bigger`): on this JIS keyboard `=` is Shift+`-`, so pressing "Ctrl+=" gives
  `key Minus {ctrl, shift} -> None` (the window turns that into Minus on purpose, keys.rs ~552, and
  Ctrl+Shift+- is readline's undo, so None is right). `Key::Equals` cannot be produced here. The same
  action through the arm that also takes Plus, `Ctrl++` (Ctrl+Shift+; on JIS), gave
  `key Plus … -> Some(FontBigger)` and 36 → 34 columns, so the action works; the listed chord was not
  pressed, so the row stays `[ ]` for a US keyboard.

## Findings

1. **Stray input reached the window while I was working**, not from this script: key-log lines
   `key ArrowRight`, `key T`, `key E`, `key Enter` with no modifiers, runs of `ControlLeft` and an
   `AltLeft` before some chords, and the text `tESTING.md` landed in a pane's prompt. The foreground was
   taken from tsumugi at times by the owner's Claude desktop app (pid 59960), which made `Send-Keys`
   throw "input not ready". I called `Set-Foreground` before every key and retried. A tick was given
   only when the key log showed the action and the PTY log showed nothing else; the stray lines are
   not counted. The unattended run shares the desktop with the owner's apps: this is the largest risk to
   a keys chunk.
2. Closing every session through the CLI (`tsumugi close` on the last one) closes the window and the
   run's server; the next start shows "Welcome back" (restore). Expected for `close`, but a test that
   closes its last session loses the window.
3. Once the window title changed from CCC to BBB between two calls with no key in the key log (probably
   the stray input of 1.). Not reproduced.
4. `make-keycheck` / `make-testcheck --check` compare the files byte for byte, so a Windows checkout with
   `core.autocrlf=true` (CRLF working files) always says "out of date". I changed the working copies of
   TESTING.md, TESTING-KEYS.md and TESTING-CHECKS.md to LF to run the check; git sees no change from that.
5. On a JIS keyboard the chord `Ctrl+=` cannot be typed (see Not ticked).

### Proposals

- The kit: `Send-Keys` could take a raw virtual key (`vk:0xBB`) so a chord can be pressed regardless of
  the layout; or the runner could switch the window's input language to en-US for the run and put it
  back. Small, and it would let `Ctrl+=` be checked here.
- Before a keys chunk the script could close or minimise the owner's foreground-stealing apps, or wait
  until the desktop is idle (no input for N seconds), instead of each run fighting for the foreground.
  Medium; it is the thing that wastes the most tokens.
- The `--check` examples could ignore `\r\n` (compare after `.replace("\r\n", "\n")`) so a CRLF checkout
  does not need a manual conversion. Small.
- The `--check` examples print nothing on success, while windows-role.md says they must "say `in sync`";
  either print `in sync` or change the sentence.
