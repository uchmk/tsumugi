## ARM64

1. **A trigger with `notify` matches the typed command line and eats the 10 s gap (rows 2.62-2.65).** In pwsh the prompt line, redrawn by PSReadLine/ConPTY when Enter is pressed, matches the second trigger when the command itself contains `Build succeeded` (`sleep 3; echo Build succeeded`). The bell note then holds a garbled run of the command text (`sleep 3; echo 'Build succeeded'sleep 3; echo 'Build succeeded'...`), and the real output 3 s later is inside the 10 s gap, so there is no toast. With the row's commands as written the check often shows nothing. The commands here were changed to build the text at run time (`'Build '+'succeeded'`), where the typed line does not match and the output does. Not changed in the code.
2. **Bell list layout.** In the bell popup the notice's long title (the `C:\Program Files\WindowsApps\...\pwsh.exe` path as the folder) runs over the time and the **trigger** label at the right, so the label cannot be read.
3. **Ctrl+C does not stop a program on this lane** (same as finding 6 of the 2.46-2.60 run): `^C` is sent (`in key ... (Ctrl+c)` in the PTY log) and `sleep 30` runs on.
4. **Kit.** The kit has no mouse drag, wheel, or held chords. The kit's `Send-Keys 'Ctrl+Shift+C'` again did not copy and went to the shell as `^C` (it did so in three tries here, with selection on screen and off screen); the same chord with the modifiers held in 120 ms steps (`keybd_event`) copied at once. That is the injection speed, as noted in the previous run, not a bug in tsumugi.
