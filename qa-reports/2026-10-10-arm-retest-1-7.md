## ARM64

- **2.44 / 2.27 (not ticked)**: with the Starship prompt (two lines, wrapped on this width) `Ctrl+Shift+L` (last output)
  copies from the row after the prompt mark, which here includes the command row, so the copy is not just the output;
  prompt jumps (`Ctrl+Shift+Up/Down`) needed two presses to move one command. With the shell's prompt replaced by `PS> `
  the output copy was exactly the output, so the mark itself works; the multi-line prompt is the difference.
- **2.3 / 2.15 (not ticked)**: moving the pointer onto the gap between two panes (`Move-KitCursor`) gave no cyan line in the
  screenshots, and a `Send-Drag` from the gap did not move the split. An earlier drag rearranged the panes (swapped them)
  instead of resizing. Either my gap coordinates were off by a pixel or the divider hit area on ARM64/this DPI is not where
  the drawn gap is. Not resolved.
- **2.37 (not ticked)**: `Ctrl+Shift+X` produces no `key X …` line in `TSUMUGI_KEYLOG` (the `ShiftLeft` and `ControlLeft` lines
  appear). A guess, not verified: egui-winit turns Ctrl+X into `Event::Cut`, so the key event never reaches the log
  (and maybe never reaches the SwapPane binding at `keys.rs:159`). The panes' order afterwards was inconsistent between tries.
- JIS keyboard: `Ctrl+=` goes out as `Ctrl+Shift+-`, and `vk 0xBB` types `;`; the kit's `Ctrl+Shift+vk:0xBB` was needed for
  `Ctrl+=`-type rows.
- A few screenshots looked one frame behind the input (PrintWindow right after a key); a short sleep fixed it.

## Proposals

- **Last-output copy and prompt jumps with multi-line prompts** (2.27, 2.44): start at the row after the *input* mark
  (OSC 133 `B`/`C`), or the row after the last prompt row, so a two-line prompt does not leak the command row into the copy.
  Small (one function in the OSC handling plus a test with a two-line prompt).
- **Log the keys egui turns into events** (Cut/Copy/Paste): add a `key X` line, or an `event Cut` line, to `TSUMUGI_KEYLOG`,
  so `Ctrl+Shift+X` and its siblings can be read as text. Small.
- **A CLI or log line for the divider under the pointer** (for example a `hover divider x,y` line in the key log): rows 2.3 and
  2.15 are pictures now and could be read. Small.
- **Older-server fixture**: keep an older `tsumugi.exe` (0.46.x) in the repo's releases or the scratch cache so 1.7, 1.11 and
  1.12 can be run by the unattended lane. Medium.
