## Bugs

**Bug 1 — `Ctrl+Shift+X` is swallowed by egui's cut event** (row 2.37).
egui-winit turns `Ctrl+X` (with or without Shift) into `Event::Cut` and the `Key::X` event never arrives, so
`keys.rs`' `(Action::SwapPane, "swap_pane", "Ctrl+Shift+X", …)` never matches. `crates/tsumugi-pane/src/input.rs:116-118` maps
`Event::Cut` to `send_chord(term, Key::X…)`, so the pane gets `\e[88;45;24;1;8;1_` (Ctrl+x chord) in the PTY log; the key log has no `key X` line.
The command palette has no "swap" entry either (`pal1.png`: "Nothing matches"), so the action cannot be reached.

**Bug 2 — `Alt+Arrows` do nothing while the find bar holds the keys** (row 2.31).
The key log says `Some(Move(Right))` with `a widget has the keys: Some(id_EFAF)` (the bar's text edit), but the focus does not move and the bar stays.

**Bug 3 — no command bars and no `Ctrl+Shift+L` copy in pwsh** (rows 2.42, 2.44).
The exit codes reach the terminal (`133;D;0/1/3` in the PTY log) but `blocks()` draws nothing and `last_output()` finds nothing. Same family as
the earlier run's Bug 3 (prompt jump does nothing in pwsh): the prompt mark's link probably does not land on the prompt's row when the prompt
starts with an empty line (Starship), or `PromptLinks` drops it. Not tried without Starship: a nested `pwsh -NoProfile` did not emit the marks
after `. h.ps1` (the hook stays off in a nested shell), so I could not separate the two.

## Kit notes

- `Send-Text 'é…'` events and `Send-Keys 'Enter'` are enough for typing; `tsumugi send N text` needs `"`r"` for the Enter.
- `tsumugi new DIR -- CMD` only types `CMD` into pwsh; quote with `& "path"`.
- `Invoke-Tsumugi ls --json` binds `ls` to `-Timeout`; pass `-Arguments 'ls','--json'`.
- The close button opens "N sessions are still running" with **Close**/Cancel; a run that closes the window must click **Close** (≈664,330).
- A nudge of the mouse and a wait is needed before `Save-Shot`, or the shot is the frame before.
- A 0-byte `.cast` while recording is normal; the file is flushed at stop.
