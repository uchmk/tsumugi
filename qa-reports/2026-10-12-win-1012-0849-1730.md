# 8.2 A restored Claude Code pane resumes its conversation (2026-10-12)

Kit config `start='claude'` (restored to `shell` afterwards); the kit was started without the `CLAUDE_CODE_*` variables of the session driving it (otherwise Claude Code says "Transcript saving is off" and keeps no conversation).

- A Claude Code pane was started from the sidebar `+` dialog and given one message ("Reply with only the word ok."); about 90 s later the card read `あなたを待っています` (Claude's idle Notification, which is how the conversation id reaches tsumugi: `notify --stdin`).
- Server stopped, tsumugi started again: Welcome back listed the pane with `会話を再開` and ticked it.
- Restore: both Claude panes came back showing the same Claude Code screen with the earlier prompt and `ok` (conversation back), card `動いています`.
- Found along the way: with no Notification having arrived (a reply and a restart within a minute), the same pane was listed as a plain `pwsh` with `で新しいシェル` and came back as an empty shell; and a `claude` typed into a shell pane is not a Claude Code pane to tsumugi. Both follow from the id coming only from the Notification hook (README, the Stop hook has no `--stdin`), so not filed as findings.
- The typed `claude --resume <id>` line itself is not in the scrollback read (`tsumugi read --all` has no `resume`), so judged from the conversation being back: `[~]`.
- Slip, no harm known: a first retry sourced the kit and then removed `TSUMUGI_ADDRESS`, so one kit window attached to the owner's server for about a minute; one click landed in a pane's text, no keys were sent, and the window was closed with Stop-Mine.
