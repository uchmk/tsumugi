## Findings

- **`TESTING-KEYS.md` on `main` is out of date** (`make-keycheck -- --check` fails at `ef6f833`): `Ctrl+Shift+O`'s description in
  `keys.rs` is now "All sessions: find a session or a line in any scrollback" (the file has `[~]` for "Every session on one
  screen"), and `Ctrl+Shift+S` (`work_log`, "Write a work log of the pane") has no line. Running the generator turns the first to
  `[ ]` (the old `[~]` was for the old behaviour) and adds the second as `[ ]`. I left the file alone; the CI check on `main` and
  the next interactive session should regenerate it. `Ctrl+Shift+S` itself worked in this run (key path of 2.70).
- Closing the last session stops the server and the window (by design); keep a spare session in a test.
- JIS board: `vk 0xBB` types `;`, `Ctrl+Shift+vk:0xBB` acts as `Ctrl++`, and `Ctrl+Shift+-` is the undo key.
- `Ctrl+Shift+X` is swallowed outside tsumugi on this machine (PowerToys or the Claude desktop?), and keys with no action
  (plain letters) do not appear in the key log; `key S … -> Some(WorkLog)` does.
- `tsumugi new … -- cmd` through PowerShell types the command into pwsh (PowerShell eats a bare `--`).
- WSL's `bash` on PATH has no distro; Git Bash is at `C:\Program Files\Git\usr\bin\bash.exe`.
- A Claude Code session started in a pane inherits the server's `CLAUDE_*` environment, and then warns "Transcript saving is off —
  inherited CLAUDE_CODE_CHILD_SESSION marker" and starts in auto mode (here from the harness; a person starting tsumugi from
  inside Claude Code would see the same).
- The conversation id reaches tsumugi only through the Notification hook: a Claude session that exits without one is listed as
  `claude=false` with 0 tokens, and its resume line is not offered.
- A narrow pane shows as a rail with the title turned sideways; it keeps its state dot.
- After a window resize, ConPTY's reflow leaves the input line's text behind in the scrollback.
- After a restart the sessions come back through "Welcome back" labelled "finished · left closed" and need Select all +
  Restore; fine, but easy to misread as lost.
- A first divider drag silently failed without a hover just before it; hover, then drag, always worked.
- The window's X shows a confirm dialog, so `CloseMainWindow` only opens it; automation must click Close.
- A work log starts with the pane's existing scrollback.
- A plain session's closed-list entry has the pwsh exe path as its title in the file (`title` = `command`), while the panel
  shows "pwsh".

## Proposals

- **Kit: double-click, window resize, cursor-shape and "same-second" helpers.** I wrote `GetCursorInfo`, a double-click and
  `SetWindowPos` by hand for 2.3/2.15/2.70. A `Send-DoubleClick`, `Get-KitCursor` and `Set-KitWindow` in `wintest-kit.ps1` would
  stop every lane from doing it again. Small.
- **Kit: keep the foreground.** The owner's Claude desktop takes it between two sends; for a two-input race (2.70's `-2`) the kit
  should send both inputs inside one `SendInput` batch or hold the desktop lock with `LockSetForegroundWindow`. Small–medium.
- **Make 2.70's `-2` a test** in `crates/tsumugi/tests/cli.rs` (two `log` requests with the same path) instead of a real-machine
  row; it is server logic with a file as the result. Small.
- **Read the log keys.** `Ctrl+Shift+X` (and Cut/Copy/Paste) never show in `TSUMUGI_KEYLOG`; a `key X` or `event Cut` line would let
  2.37 be read as text. Small.
- **Large OSC 1337 images are slow** (37–91 KB: 10–15 s before the prompt returns). Decoding or the escape parser looks quadratic.
  Medium; worth a profile.
- **A `tsumugi log N [PATH]` CLI** would let a lane start and finish work logs without the key or the menu, and make 2.70/2.71 text rows.
  Small.
- **Older-server fixture** for 1.7/1.11/1.12: keep one old `tsumugi.exe` (0.46.x) next to the scratch cache, or let
  `scripts/auto-wintest.ps1` fetch the previous release's `.zip` from GitHub into `kit\old\`. Medium.
