## Findings (failures)

### 2.52 — pwsh loses plain SGR and the underline never resets

In PowerShell 7 started by tsumugi, `Write-Host` with the row's escapes is rewritten by OpenConsole before it reaches the
PTY. PTY log `out` line:

```
a u \e[4:2mdd \e[4:3;58;2;255;0;0mcurl \e[4:4mdots \e[4:5mdash strike [hid]\r\n
```

The plain `\e[4m`, `\e[9m`, `\e[8m` and every `\e[0m` are gone. On screen (`s252_pwsh`): `u` is not underlined, `strike` is not
struck, `[hid]` is shown, `dd` is underlined, and the red wave under `curl` carries on under the next prompt line.
In Git Bash (`bash.exe --login -i`, a split pane) the same test logs every SGR intact (`\e[4:` `3;58;2;255;0;0mcurl`
`\e[0m`, `\e[9m`, `\e[8m`) and `s252_bash` shows single, double, red wave, dots, dashes, strike and `[   ]` blank correctly.

`OpenConsole.exe` **does** sit beside the server's exe: `R:\Temp\run-20261011-035005\kit\server\OpenConsole.exe`
(1.24.2607.10001, 1 066 296 bytes, copied from `target\release`) next to `tsumugi-0.85.0-….exe`. So the failure is not a
missing ConPTY. The "close the window and open it again" step was not run, since pwsh already fails.

### 5.8 — `Ctrl+Shift+O` again does not close "All sessions"

On a 1280 × 800 window with waiting, running, quiet and done sessions: the list order was Waiting, Running, Running (quiet),
Done, each row with its state, folder, branch, tags and last two lines; Down ×3 then Enter went to the done pane (marker
only in its `tsumugi read`); a click on a row went to that pane; `Ctrl+Tab` ×2 gave Waiting then Recently closed;
`Ctrl+Shift+Tab` Waiting; Right Recently closed; Left Waiting. All as the row says **except** pressing `Ctrl+Shift+O` again,
which leaves the page open (tried three times; only `Esc` closes it). The key log reads
`key O … -> Some(Overview); a widget has the keys: Some(id_…)` and the page stays (`s58_toggle_try`).

Cause, from the source: `main.rs` ~5378 sets `field` whenever `self.lists.is_some()`, and the branch that collects window
shortcuts (~5505) only runs with `!field`, so the toggle at ~1736 (`Some(v) if v.page == lists::Page::All => None`) is never
reached while the page is open.

### 5.10 — the help panel overflows at 1280 × 800 after a resize

Fresh at 1280 × 800 (`s510_1280`) `F1` shows four columns with every group and no scrollbar. At 1000 × 700 (`s510_1000_open3`)
it shows three columns with smaller letters and no scrollbar at rest (a thin bar shows on hover). `F1`, `Esc` and a click
outside (on the title band) each close it at both sizes. But after the window had been 1000 × 700 and was set back to
1280 × 800, `F1` opens it with larger letters (`s510_1280_open3`): the last row of ALL SESSIONS and of THE SETTINGS SCREEN are
cut off at the bottom, so it needs a scroll (a scrollbar showed when a click landed inside it). Reproducible on re-opening
twice. A click inside the panel does not close it (correct).

### 17.26 — Restart the server does not bring the server back

Settings → Advanced showed "Running · 0.85.0 · 18m"; pressing **Restart**: within 0.7 s the window shows only
"The tsumugi server went away." (never "Restarting the server…"), the side card stays stale (`s1726_r1`), and the status
bar keeps "mux · up 18m". It stayed so for over a minute (`s1726_late2`). `tsumugi ls` says `no server (os error 2)`; no
server process was running; the saved `state` file was written at the stop (the four panes are in it). So the stop worked
and the start did not: no "Welcome back", no tabs, no uptime restart. Starting `tsumugi server` by hand afterwards worked,
so the exe and `OpenConsole.exe` are fine. `restart_server` (`main.rs` ~3797) clears the client and calls `replace_server`;
the likely line is `main.rs` ~5147, where `client.lost()` with `failed` already cleared sets "went away" — i.e. the answer from
`replace_server` was an error or the new client was lost at once. I did not dig further.

### Proposals

- `Ctrl+Shift+X` and `Ctrl+Shift+L` sent quickly lose Shift (egui turns them into `Cut` / `Copy` events); they work with
  `Send-Keys -Hold`. Probably only a test-harness matter, but a real fast typist may hit it.
- `tsumugi new -- pwsh` starts a nested, unhooked pwsh (no OSC 133 marks): `Ctrl+Shift+Up/Down` and `Ctrl+Shift+L` do nothing
  there. Use `tsumugi split` for hooked panes.
- 2.44: `Ctrl+Shift+L` in a pane whose prompt line was reflowed/garbled (after a swap that changed the width) copied only the
  last output line. Mark boundaries seem to be confused by a reflow; worth a look.
- The first character after a window resize or a focus change is swallowed (typed `cho` for `echo`). Not a product finding,
  but a test must `Set-Foreground` and wait first.
- Let the overview key close the page when it has the keys (5.8).
- 17.26 should show "Restarting the server…" (the code sets it) and, if the new server fails to start, say why.
