## 目標: cmux を超える

[cmux](https://github.com/manaflow-ai/cmux) は Ghostty の上に作った macOS 専用のターミナル。
複数のコーディングエージェントを並べることに絞っている。

| cmux にあるもの | 中身 |
| --- | --- |
| 縦タブのサイドバー | ワークスペースごとに Git のブランチ、つながっている PR の状態と番号、作業フォルダ、待ち受けているポート、最新の通知の文を出す |
| 通知 | OSC 9 / 99 / 777 を拾う。`cmux notify` の CLI をエージェントのフックにつなぐ。待っているペインは青い輪で囲まれ、サイドバーのタブが光る |
| 分割 | 縦横に分割できる |
| 組み込みのブラウザ | スクリプトで操作できるブラウザのペイン。エージェントがアクセシビリティツリーを読み、クリックやフォームの入力をする |

**tsumugi が超えるところ**（v1 で入れるものに ★）

1. ★ **Windows で動く。** cmux は macOS だけ。tsumugi は Windows x64 / ARM64 から始め、macOS と Linux にも広げる。
   これだけで、Windows で Claude Code を並べたい人には唯一の選択肢になる。
2. ★ **フックを仕込まなくても「待っている」が分かる。** cmux はフックか OSC の通知を送ってもらう前提。
   tsumugi はそれに加えて、ターミナルが自分で見えるものから判断する: シェルのプロンプトが戻った（OSC 133）、
   窓のタイトルの変化、子プロセスが入力を読もうとして止まっている、出力が一定時間止まっている。
3. **専用の入力欄。** 複数行のプロンプトを普通のエディタの欄で書き、まとめて送る。TUI の中で `Shift+Enter` と戦わない。
4. ★ **セッションの復元。** 分割の形、各ペインの作業フォルダ、起動したコマンドを保存し、再起動後に戻す。
   Claude Code なら `claude --resume` で会話ごと戻す。
5. **セッションの見える化。** タブごとに、送ったプロンプトの数、かかった時間、（取れれば）トークン数。
6. ★ **マルチプレクサ。** 窓を閉じてもセッションが生き続け、開き直せばそのまま戻る（下の節）。cmux は窓を閉じればシェルも終わる。
7. ★ **画面がかっこいい。** 道具として速いだけでなく、見て気持ちのよいものにする（下の節）。

cmux の組み込みのブラウザは v1 に入れない（大きく、OS ごとに作りが変わる。v2 以降で検討）。

## v1 に入れるもの

1. **縦タブのサイドバー。** タブ 1 つが 1 つのワークスペース（分割した複数のペインを持てる）。
   タブに出すもの: 作業フォルダ、Git のブランチ、Claude Code が窓のタイトルに出す作業名、状態。
1a. **タグ。** セッションに自分で名札（`#review`、`#ci` など）を付ける。色付きの小さな札でタブに出し、サイドバーの上の札で絞り込む。
   フォルダから自動で付ける規則（`~/dev/filer` なら `#filer`）を設定に書ける。CLI は `tsumugi tag <セッション> <タグ>`。
   見本: https://claude.ai/artifact/Khz9acDdjngtNS4LKyffiK （持ち主だけが開ける）
1b. **並べ替えと絞り込み。** タブはドラッグで並べ替える（つかむ所はタブに乗せたときだけ出る）。並びの規則は 5 つから選ぶ:
   手で並べた順（既定）、手を待っているものを先に（入力待ち → エラー → 動いている → 終わった）、最近動いた順、フォルダ順、名前順。
   サイドバーの下で、状態（入力待ち・動いている・エラー・終わった）とフォルダで絞り込め、組み合わせられる。
1c. **メニューバーは持たない。** 窓の上の真ん中に検索欄（`Ctrl+Shift+P`）を置き、セッション・フォルダ・コマンドをここから探す。
   右上に、選んでいるセッションのタグを Proxmox 風の塗りの札で出す。
1d. **ステータスバー。** 左にサーバーの状態と、状態ごとのセッションの数。真ん中に選んでいるペインのフォルダ、ブランチと push していない数、PR と CI。
   右に今日のトークン、シェルと大きさ、文字コード。
1e. **フォーカス（キーが入るペイン）**: 選んでいないペインの中身を暗くし（状態の輪は暗くしない）、塗りのカーソルは選んでいるペインだけ、
   他は枠だけのカーソル。暗くする強さは設定で変えられる。
1f. **分割**: ふだんは隙間だけで、近づくと水色の線とつまみ（つかめる幅 12px、ダブルクリックで半分ずつ）。`Ctrl+Shift+Z` で 1 つを全画面にし、
   隠れたペインが待っていれば金の札で知らせる。見出しをつかんで運び、上下左右と真ん中の的で分割か入れ替え。20 桁 × 4 行より狭ければ名前と状態だけの帯に畳む。
   サイドバーとペインの間の境目も同じ作りで、ドラッグで幅を変える（200〜480px、幅は覚えておく）。ダブルクリックで既定の幅に戻す。
1g. **新しいセッション**: `Ctrl+Shift+T` で、今のペインのフォルダが入ったダイアログ。フォルダ → 起動するもの（Claude Code / 前回の続き / シェル / プロファイル）→ タグ。
   `Enter` で新しいタブ、`Alt+Enter` で右に分割。フォルダ・起動するもの・タグ・分割の形を「プロファイル」として保存できる。
1h. **窓の外への知らせ**: 窓を見ていないときだけ。OS の通知・タスクバーの数字・タスクバーの点滅・音の 4 つを、入力待ち・エラー・終わったの
   状態ごとに ON / OFF できる。既定は通知（3 つとも）と数字（入力待ちとエラー）だけ ON。「終わった」は 1 分以上動いたときだけ。タグごとに知らせない設定もできる。
1i. **セッションが多いとき**: 3 つの形を全部入れる。ふつうのタブ（既定）、1 本 1 行に詰めた形（12 本を超えたら切り替えるかを 1 回だけ聞く）、
   細い帯のレール（幅 60px、フォルダの頭文字と状態の輪、`Ctrl+B` か境目を 120px より左へ引く）。並べ替えで「Folder」を選ぶと、フォルダの見出しで畳めるまとまりになり、
   開いたまとまりでも手の要るものだけを見せて残りは「+ N more」にする。
1j. **タブの右クリックメニュー**: ① 名前・タグ・通知を止める・上に留める ② 再起動（会話を続ける）・同じフォルダでもう 1 本・別の窓へ
   ③ filer でフォルダを開く・エディタで開く・パスをコピー ④ 閉じる（赤、一番下）。**項目は設定で変えられる**: `settings.toml` の
   `[[menu.session]]` に名前・キー・実行するコマンドを書いて足し、並べ替え、隠す（filer の `[opener]` と同じ考え方）。設定の画面からも隠す・並べ替えができる。
1k. **テーマ**: 暗い（既定）・明るい・OS に合わせる、の 3 つ。設定の画面（Appearance）で選べ、`settings.toml` の `theme = "dark" | "light" | "system"` と同じもの。
   色を細かく変えるときは `theme.toml` に書く（書いた色だけが既定を上書きする）。明るいテーマは見本の 9 の色。
   **組み込みのテーマを 10 種ほど用意し、設定の画面のプルダウンで選ぶ**（選んでいる間は画面に即座に映す）。候補: tsumugi Dark / Light（filer と同じ色）、
   Tokyo Night、Catppuccin（Mocha / Latte）、Dracula、Nord、Gruvbox（Dark / Light）、Solarized（Dark / Light）、One Dark、Rosé Pine。どれも MIT などで同梱でき、出典を書く。
   テーマごとに「入力待ち・動いている・エラー・終わった」の 4 色を、そのテーマの黄・水色・赤・緑から決め、白地 / 黒地で読める濃さに合わせる。
   設定フォルダの `themes/` に置いた `.toml` もプルダウンに並ぶ。Windows Terminal と iTerm2 の配色ファイルを読み込めるかは後で決める。
1l. **専用の入力欄**: 見本の 12 の形（`Ctrl+I` で出し入れ、`Enter` は改行・`Ctrl+Enter` で送る、画像は添付、`↑` で履歴、送り先をタグで選べる）。
   v1 の次に入れる。
1m. **設定の画面**: 1 つの設定のタブ（`Ctrl+,`）に 9 つの分類（General / Appearance / Keys / Notifications / Sessions & profiles / Tags / Theme /
   Shell & hooks / Advanced）。Theme は見本の 9b（テーマの一覧と即座に変わるプレビュー。プルダウンにはしない）。Appearance はフォント・窓・動き。
   Notifications は見本の「知らせ方」の表（4 × 3 の選択は表が一番分かりやすいので、他の分類と作りが違ってよい。見出しと余白はそろえる）。
1n. **時計**: ステータスバーの右端に `2026/10/05 (Mon) 14:32`（最大化しても全画面でも見える）。General で、時刻の形式（12 / 24 時間）、日付を出すか、
   日付の形式（YYYY/MM/DD・YYYY-MM-DD・MM/DD/YYYY・DD/MM/YYYY）、曜日を出すか、を選べる。
1o. **タグの数**: 1 本につき最大 5 個。タイトルバーとタブには 3 個まで出し、残りは `+2` の札（乗せるか押すと全部）。
   窓が狭くなったら、タイトルバーではタグが先に `+N` に畳まれ、次にコマンド欄が虫眼鏡のボタンに縮む。
2. **状態と通知の印。** 状態は「動いている / 入力待ち / 終わった / エラー」の 4 つ。入力待ちになったタブとペインに印を付ける。
   知る手段は 3 つを重ねる: Claude Code のフック（`Notification` / `Stop`）から `tsumugi notify` を呼ぶ、OSC 9 / 99 / 777、
   ターミナル自身の観察（上の 2）。
3. **分割。** 縦横の分割、境目のドラッグ、キーでのペイン間の移動。分割の仕組みは共有のクレート（`tsumugi-layout`）。
4. **セッションの保存と復元。**
5. **filer のペインをそのまま使う。** ConPTY（新しい版を同梱）、win32-input-mode、OSC 7、マウスの報告、検索、スクロールバック。

## マルチプレクサ（2026-10-05、持ち主の方針）

Claude Code の作業は何十分も続く。窓を閉じた、PC を再起動した、GUI が落ちた、で会話ごと消えるのは困る。
tmux や zellij のように、**セッションを持つのは裏で動くサーバー（`tsumugi-mux`）、窓はそれにつなぐクライアント**の形にする。

- **v1: 手元のサーバー。** GUI を閉じてもサーバーと中のシェル・Claude Code は動き続け、次に開いた窓がつなぎ直す。
  GUI が落ちても作業は消えない。サーバーとの間は OS の仕組みで閉じる（Windows は名前付きパイプ、Unix はドメインソケット）。
  WezTerm の mux や zellij と同じ考え方。「保存と復元」の大半はこれで済み、残りは PC の再起動をまたぐ分（分割の形と `claude --resume`）だけになる。
- **v1: CLI。** `tsumugi ls`（セッションの一覧と状態）、`tsumugi attach <名前>`、`tsumugi notify`（フックから印を送る）、`tsumugi new <フォルダ> -- claude`。
  エージェントや自分のスクリプトから tsumugi を操作できる。
- **v2: tmux とつなぐ。** iTerm2 の tmux 統合（`tmux -CC` の制御モード）と同じく、SSH の先や WSL で動く tmux のウィンドウとペインを、
  tsumugi の本物のタブと分割として描く。リモートの機械で動く Claude Code も、手元のものと同じサイドバーに並ぶ。
- **v2 以降: リモートのサーバー。** 別の機械の `tsumugi-mux` に SSH 越しにつなぐ（WezTerm の SSH ドメインと同じ）。

## 見た目（2026-10-05、持ち主の方針: かっこよく）

- **GPU で描く。** egui + wgpu。スクロールも分割の境目のドラッグも 60fps（高リフレッシュの画面ではそれ以上）で滑らかに。
- **状態を色と動きで見せる。** 入力待ちのペインは枠がゆっくり脈打つ光、動いている間はタブに細い進捗の線、エラーは赤の印。
  派手にしすぎず、目の端で気づける強さにする。
- **窓の素材。** Windows 11 は Mica / Acrylic（背景のにじみ）、macOS は vibrancy。設定で切れる。
- **文字。** 合字（ligature）、Nerd Font のアイコン、太字と斜体の別のフォント、行の高さの調整。
- **テーマ。** 既定のテーマを 1 つ作り込み、明暗の 2 つを用意する。色は 1 つのファイルで差し替えられる。
- **動きは短く。** タブの切り替え、分割、通知の出入りに 100〜150ms の短い動き。設定で止められる。
- **最初の画面から見せられるものにする。** v0.1.0 の時点で、スクリーンショットを README に載せて恥ずかしくない見た目にする。

## v1 に入れないもの

- 組み込みのブラウザ、画面のキャプチャ、音声の入出力（構想の 4）
- 専用の入力欄（構想の 1。v1 の次に最優先で入れる）
- 設定のコード化（Lua など。filer で Lua を入れなかった理由をどう扱うかを先に決める）
- tmux の制御モードとの統合、リモートのサーバー（マルチプレクサの v2）
- 汎用のターミナルとしての作り込み（Windows Terminal や WezTerm と張り合わない）

## 決めたこと（2026-10-05、持ち主の回答）

- **共有のクレートはこのリポジトリの workspace に置く。** filer は git の依存で読む。
- **名前は `tsumugi-pane`（ターミナルのペイン）と `tsumugi-layout`（分割）。** サーバーは `tsumugi-mux`。
- **サーバーは最後のセッションが終わったら止まる。**
- **既定のテーマは filer と同じ色から始め、テーマのファイルで変えられるようにする。**
  filer の既定の文字色（`fg` `#c8cdd8`）は背景（`#16181d`）に対してコントラスト比 11.2 で十分読める。
  一方、薄い文字（`fg_dim` `#798090`）は 4.5 で、小さい文字に求められる 4.5 の境目にある。tsumugi ではサイドバーの補足情報に
  薄い文字を多く使うので、`fg_dim` を少し明るく（6 以上）する。
- **既定のキーと「入力待ち」の条件は、下の案で進め、使ってみて直す**（持ち主は案を求めた）。QUESTIONS.md の Q1 と Q2。
